# mock-server

Учебный сервер на [Express](https://expressjs.com/). Логика — в файле server.js. Данные в файле db.json.

## Запуск

Требуется Node.js 18.18 или новее.

```
npm i
npm start
```

Сервер доступен по `http://localhost:3001`. 

При открытии в браузере `http://localhost:3001/tasks` — должен появиться список задач в формате JSON.

## Что умеет сервер

| Запрос | Что делает | Ответ |
|---|---|---|
| `POST /login` | проверяет логин и пароль; тело запроса `{ "login": "demo", "password": "demo123" }` | 200 `{ user }`; 400 — поля не заполнены; 401 — неверная пара |
| `GET /tasks` | все задачи; `?status=todo` — только с нужным статусом | 200 |
| `GET /tasks/1` | одна задача | 200; 404 |
| `POST /tasks` | создать задачу (данные в теле запроса, обязательно `title`) | 201; 400 |
| `PATCH /tasks/1` | изменить поля, например `{ "status": "done" }` | 200; 404 |
| `DELETE /tasks/1` | удалить задачу | 204; 404 |

Пользователи для входа: demo / demo123.

## Как проверяется вход

1. Приложение отправляет `POST /login`, а логин и пароль кладёт в тело запроса.
2. Сервер ищет в `db.json` пользователя с такой парой (`db.users.find(...)`).
3. Не нашёл — отвечает кодом **401** и сообщением «Неверный логин или пароль».
4. Нашёл — отвечает кодом **200** и данными пользователя (без пароля).

Пример для консоли браузера (DevTools → Console), когда сервер запущен:

```js
const res = await fetch('http://localhost:3001/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ login: 'demo', password: 'demo123' }),
})
console.log(res.status, await res.json())
```

## Как менять сервер

Откройте `server.js`: у каждого маршрута есть комментарий. Простые правки:

- **Запретить вход заблокированному пользователю.** В `db.json` добавьте пользователю поле `"blocked": true`, а в маршрут `POST /login` после проверки `if (!user) {...}` допишите:
  ```js
  if (user.blocked) {
    res.status(403).json({ message: 'Учётная запись заблокирована' })
    return
  }
  ```
- **Проверять статус задачи.** В `POST /tasks` добавьте проверку: если `status` не `todo`, `in-progress` или `done` — ответить кодом 400.
- **Фильтр по приоритету.** В `GET /tasks` по образцу фильтра `status` добавьте фильтр по `req.query.priority`.
- **Своя сущность в проекте.** Добавьте в `db.json` пустой массив, например `"projects": []`. Скопируйте пять маршрутов `/tasks` из `server.js`, замените в копии `tasks` на `projects`, `/tasks` на `/projects` и подправьте поля.

## Частые проблемы

- **`Failed to fetch` в приложении** — сервер не запущен или в приложении указан не тот порт. Откройте адрес в браузере напрямую.
- **Порт 3001 занят** — завершите прежний запуск (Ctrl+C в его терминале) или смените порт в последней строке `server.js`.
- **Сервер не стартует после правки** — прочитайте сообщение в терминале: обычно это опечатка или незакрытая скобка.
- **Ответ 500 или пустой ответ** — смотрите терминал: частая причина — лишняя запятая или незакрытая кавычка в `db.json` после ручной правки.
- **Новый маршрут не работает** — проверьте, что он добавлен до блока «Запуск» и что после правки файл сохранён.

## Важно о безопасности

Сервер *учебный*: пароли лежат в `db.json` открытым текстом, сервер не запоминает, кто вошёл, и не защищает остальные адреса. В настоящих приложениях пароли хранят в виде хэшей, а после входа выдают токен, который проверяют при каждом запросе.
